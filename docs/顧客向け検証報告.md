# 工場建設レイアウト探索 PoC — 顧客向け検証報告

対象: 建設業のお客様。工場建設時に、入庫から製造、出庫までの流れを満たすレイアウト案を複数提示する。

本資料は、動いている MVP への途中参画として、アルゴリズム検討・実装・サンプル検証の結果を説明するためのものです。返る案はヒューリスティックであり、厳密な最適解ではありません。

## 1. お客様要件との対応

| 要件 | PoC での扱い |
|---|---|
| 条件を満たすパターンを探索する | 敷地・非重複・通路・離隔・固定棟をハード制約として、実行可能配置だけを残す |
| 入庫→製造→出庫の一連の流れ | 工程チェーン（受入→加工→組立→検査→出荷）が北から南へ進むかを評価する |
| 複数提案 | 複数スタートの組み合わせ探索で、配置が異なる案を最大8件まで返す |
| 顧客説明可能な MVP | Web 画面で初期解と各案を並べ、費用内訳・提案理由・工程パスを表示する |

## 2. 検討した解法と採用理由

| 候補 | 判断 |
|---|---|
| 整数計画（厳密解） | 建屋サイズが異なる二次割当に近く、PoC の応答時間と説明コストが大きい。将来比較用に残す |
| 貪欲法のみ | 速いが、局所的に悪い配置で止まり、複数案が作れない |
| 遺伝的アルゴリズム | 多様性は出るが、パラメータ説明が重い |
| **採用: 貪欲 + 複数スタート + 焼きなまし** | 実行可能解を必ず作り、異なる種から複数パターンを出し、改悪受理で局所解を抜ける。再現は seed で固定できる |

近傍は「1棟の再配置または回転」です。建屋寸法が違うため、単純な2棟入替は使っていません。

## 3. サンプルデータ（組立工場）

- 敷地: 10行 × 12列。中央 2×2 は通路（禁止セル）
- 工程: 受入（入庫）、機械加工・組立・検査（製造）、出荷場（出庫、南側固定）、事務所・危険物庫（付帯）
- 物流: 受入80→加工70→組立50→検査45→出荷
- 隣接希望: 受入—加工、検査—出荷
- 離隔: 危険物庫と事務所は 3 セル以上

## 4. 検証結果

バックエンド自動テスト（pytest）で次を確認しています。

| 検証 | 結果 |
|---|---|
| 2×2・3工程の全列挙最短費用とヒューリスティック最良案が一致 | 合格 |
| 物流の大きい2工程が隣接する | 合格 |
| 7工程サンプルが実行可能。出荷場は南側固定のまま | 合格 |
| 危険物庫と事務所の離隔 3 セル以上 | 合格 |
| 同じ seed で同一配置を再現 | 合格 |
| 工程チェーンが逆行する配置は費用が悪化する | 合格 |
| 置けない寸法・空データはエラー | 合格 |
| Web API が複数案（案1…）を返す | 合格 |
| 提案理由（短縮した物流）と工程パスを返す | 合格 |
| 2×2・3工程では厳密最良とのギャップを返す | 合格（サンプル規模では全列挙しない） |

高度化前（seed 1/2/3/7/11、提案数3、改善周回40）では、貪欲初期解 2207 が逆行し、5種のうち2種は整列案を1件も返せませんでした。

高度化後（チェーン誘導貪欲 + 逆行修正/2棟交換 + 多様な複数スタート）:

| 指標 | 高度化前 | 高度化後 |
|---|---|---|
| 貪欲初期解 | 2207・逆行 | 1539・南方向に整列 |
| 案1が整列した seed | 3 / 5 | 5 / 5 |
| 整列案の割合 | 5 / 15（33%） | 13 / 15（87%） |
| 案1の平均費用 | 1243 | 1184 |
| seed=1 の案1 | 1204・隣接1/2 | 1104・隣接2/2 |

サンプル seed=1（提案数3、改善周回40）の実測例:

| 案 | 総費用 | 物流 | 隣接 | 流れペナルティ | 入庫→出庫 |
|---|---:|---:|---:|---:|---|
| 初期（貪欲） | 1539 | 1539 | — | 0 | 南方向に整列 |
| 案1 | 1104 | 1104 | 0 | 0 | 南方向に整列 |
| 案2 | 1151 | 1151 | — | 0 | 南方向に整列 |
| 案3 | 1421 | 1413 | — | 0 | 南方向に整列 |

物流下界は 761（2棟だけの最短。他棟競合は無視）。ヒューリスティック案1との推定ギャップは 343（31.1%）でした。

厳密モード（分枝限定、制限 25 秒）では目的関数 **878** の配置を証明済みの最適解として返します。ヒューリスティック案1（1104）より 226 短いです。時間切れのときだけ「未証明の最良解」と表示し、最適とは書きません。

表示順は「流れが整列している案」を先にし、その中で費用が小さい順です。物流だけ短い逆行案も多様性確保のため残すことがあります。

画面操作: 「レイアウト探索」を押すと案1〜案3が並び、選んだ案と初期解のグリッドを比較できます。各案には「どの物流が短くなったか」の理由文と、入庫→出庫の工程パス（緑→赤）を重ねて表示します。2×2 のような小規模問題だけ、全列挙した厳密最良とのギャップを数字で出します。サンプル工場は建屋が 1×1 ではないため、厳密ギャップは出しません。

## 5. 顧客説明時の言い方

- 「最適レイアウト」ではなく「条件を満たす候補の中で、物流距離が短い案」
- 案が複数ある理由は、建設制約（動線・危険物・固定棟）の下で取りうる形が一つに決まらないため
- 数字はセル単位の相対距離。実寸法に換算すれば概算搬送量の比較に使える
- 通路形状・階数・ユーティリティ容量・法令チェックは未実装

## 6. 今後の拡張

1. お客様実データ（建屋寸法、物流OD、固定設備）での再検証
2. 出庫を複数ドックにする、入庫を東面に固定するなどの現場制約
3. 整数計画ソルバとの比較（建屋サイズが異なる本規模。現状の厳密ギャップは 1×1 かつ敷地9セル以下のみ）

実装済み（本PoC）:

- 提案理由の文章化（初期解比で短縮した物流、隣接、工程整列）
- 工程チェーンのパス重ね描画
- 1×1・小敷地の全列挙ギャップ
- チェーン誘導貪欲、逆行修正、2棟交換、多様性選択
- 物流下界・推定ギャップ・隣接達成・整列案数の有効性指標
